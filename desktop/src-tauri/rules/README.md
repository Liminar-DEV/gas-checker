# Правила детекта

Движок чекера (обход дисков, чтение zip, потоки, прогресс, отправка, интерфейс) открыт. Всё, что говорит, **как
именно** ищутся читы, вынесено в один файл правил, который в репозитории хранится зашифрованным.

## Как это устроено

| Файл | Что это |
|---|---|
| `private/rules_private.rs` | полные правила в открытом виде. Лежит только у владельца, в `.gitignore` |
| `rules/rules_private.rs.enc` | то же, зашифровано (AES-256-GCM, формат: 12 байт nonce, шифртекст, 16 байт тега). Коммитится |
| `src/rules_open.rs` | открытая заглушка с тем же интерфейсом: ловит только клиенты с публичным кодом |

`build.rs` собирает `OUT_DIR/rules_active.rs`, а `main.rs` подключает его как `mod rules`:

- Задана переменная `GASCHECKER_RULES_KEY` (64 hex-символа) и файл `.enc` есть: файл расшифровывается и становится
  правилами. Если расшифровать не вышло (неверный ключ, повреждённый файл), сборка **падает с ошибкой**, молчаливого
  отката на слабые правила нет.
- Ключа или файла нет: берётся `src/rules_open.rs`, при сборке выводится предупреждение, а в окне программы
  показывается заметка «сборка с открытыми правилами». Команда `rules_edition` отдаёт интерфейсу `"full"` или `"open"`.

## Владельцу: ключ и шифрование

Все команды выполняются в папке `desktop`.

```bash
npm run rules:genkey                      # печатает новый ключ, никуда его не сохраняет
export GASCHECKER_RULES_KEY=<ключ>        # PowerShell: $env:GASCHECKER_RULES_KEY="<ключ>"
npm run rules:encrypt                     # private/rules_private.rs -> rules/rules_private.rs.enc
npm run rules:decrypt                     # обратно: в stdout (или `-- файл`)
```

1. Сохраните ключ в менеджере паролей. Потеряв его, вы не расшифруете `.enc` (останется только `private/`).
2. Добавьте ключ в секреты GitHub: Settings → Secrets and variables → Actions → `GASCHECKER_RULES_KEY`.
   Релизный workflow передаёт его в сборку.
3. Закоммитьте `rules/rules_private.rs.enc`. Ключ и `private/` не коммитьте.

## Как менять правила

1. Правьте `private/rules_private.rs`.
2. Прогоните `cargo test` с ключом (после `rules:encrypt`), проверьте результат.
3. Зашифруйте заново: `npm run rules:encrypt`, закоммитьте новый `.enc`.

Интерфейс (имена, которые зовёт движок) должен совпадать в `rules_private.rs` и `src/rules_open.rs`. Меняя его,
правьте оба файла.

## Ограничения

- Шифрование прячет правила от тех, кто читает исходники. Работающий `exe` содержит правила в открытом виде, и их
  можно достать реверсом.
- Контрибьюторы не видят и не меняют приватные правила. Предложения по ним вносятся владельцем.
- Сборка из исходников без ключа даёт только открытые правила: проверка частичная.
- Результат присылает клиент на ПК игрока, и тот, кто знает код проверки, может его подделать. «Чисто» ничего не
  гарантирует.
